# Small context, useful memory

Resume from a short `state.md`: incumbent and evaluation, active jobs, current bottleneck, live hypotheses and next decision. Reconcile job/submission status before relaunching. Search relevant history and code; do not reload the full corpus or raw logs.

Use an append-only experiment ledger or an equivalent existing tracker. Keep the record sufficient to reconstruct the comparison: hypothesis/family, parent and changed factors, code/config/data/split identities, measured results, artifact locations and decision. Job IDs and seeds matter when relevant. No fixed schema or lengthy report is required.

Distinguish proposed, running, completed, investigated, promoted and submitted. A seed repeat is another run of the same hypothesis; a dashboard snapshot is not a new experiment.

After an important result, retain a short reusable finding: **mechanism, conditions, evidence, failure cases, next transfer**. Link the reproducing artifact. Keep rejected ideas conditional; do not turn one failure into a universal prohibition. Revisit a failure when its prerequisite or implementation has changed.

Write metrics and diagnostic summaries from job outputs. Keep large predictions, raw logs and execution details in run artifacts. Record concise decisions, not internal reasoning transcripts.

User communication: three short lines, **Result / Decision / Next**, at meaningful changes or when asked. Report blockers precisely and continue independent work. Concise chat does not excuse missing evidence.
